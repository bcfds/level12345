# [Level] 代码编写规范
灵感来自https://www.mcmod.cn/post/6071.html
## 1. 前言与目标
- 统一团队代码风格，提高可维护性
- 降低新人上手成本

## 2. 主类
- 主类只用于获取模组总线启动其他模块，禁止在其中塞入游戏逻辑

## 3. 命名约定
- 包叫Modxxx,遵从驼峰命名(如装有level1就叫ModLevel1
- 类用名词，遵从驼峰命名
- 方法用动词，遵从驼峰命名
- 常量全部大写

## 4. 项目结构与包划分
- 按照功能分包而不是功能类型
- 例如:实现理智的网络包放在ModCapabilities/Sanity下而不是network下，因为我们是按照功能完成的分工

## 5. 注册系统（DeferredRegister）
- 所有注册在对应功能包内实现，便于管理

## 6. 事件与生命周期
- 事件订阅@注解，但是涉及到使用MOD总线的请显式的在主类中使用XXX.XXXX.register(modEventBus)传入
- 类组织按照功能
- 模组总线不进功能包，游戏总线不出功能包

## 7. 客户端与服务端分离
- 时刻提醒自己注意物理端判断
- 关于是否需要server/client分离待议

## 8. 网络通信
- SimpleChannel 使用规范
- 包编解码与主线程调度

## 9. 数据生成
- 使用生成器，严禁手写JSON

## 10. 注释与文档
- 勤写注释，注释内容应说明类/方法功能和实现逻辑，保证只读注释就可以直接使用类/方法
- TODO写代办的功能增加项
- FIXME写影响游玩的逻辑(例如写了数据需要别人帮忙网络同步就用FIXME而非TODO)

## 11. 日志、配置与国际化
- 有操作，有日志
- 配置en和ch足以，莫要AI贪杯

## 12. 禁止事项
- 禁止静态字段直接 new 注册对象
- 禁止在 tick/渲染循环创建新对象（避免 GC 压力）
- 禁止硬编码数字和资源路径
- 禁止在网络线程直接修改世界

## 13. Git 提交规范
- 提交信息书写明确的提交内容，无明显更改也写出"无明显更改"
